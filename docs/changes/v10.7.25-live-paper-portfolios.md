# Front v10.7.25 — Portfolio Live e Trading (Paper) segregados

**Branch:** `feature/live-paper-isolated-workspaces-v1`, criada a partir da `main` v10.7.24. Merge/deploy não efetuados.

**Mudança:** o Portfolio passa a ter abas internas **Trading (Paper)** e **Live**, renderizando os mesmos componentes de métricas, evolução, contribuições por ativo, ranking e tabela de auditoria, porém consultando rotas diferentes. Cada aba é desmontada/remontada por chave ao alternar, impedindo persistência de respostas Paper na visão Live. Exportação de auditoria utiliza ZIP distinto para cada corretora/ambiente. Abas Live reservadas a `admin.manage` e API Live protegida por sessão administrativa.

**Live:** conexão com `/api/live-market/portfolio`, status de leitura com `/api/live-market/robot/status` e auditoria com `/api/live-market/portfolio/export.zip`. Não criar histórico de decisões/modelos não existentes, nem métricas financeiras não justificadas. Contas com múltiplas posições são exibidas corretamente, sem identificá-las como caixa.

**Operação do Trader:** seção Paper mantida funcional; nova seção Live com mesmos quatro controles desenhados, **todos desabilitados** até instalação do executor Live. Isto evita botão “Iniciar” fingir execução ou usar indevidamente rotas Paper. Monitor Paper deixa de exibir a lista `Log execução`, preservando progresso e dados de auditoria. Nenhum log persistido foi removido.

**Segurança:** nunca enviar chaves Live ao frontend. Credenciais exclusivas na API Railway. A Winner #30 continua única referência imutável, mas Paper/Live não compartilham saldo, ordens, agendador ou plano.

**Teste:** build Vite na CI do PR; verificação manual alternando as abas e conferindo que a resposta Live não contém CAPR Paper, e que exportações e controles são independentes. Live permanece apenas para consulta mesmo se houver capital.
