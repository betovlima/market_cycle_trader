# Front v10.7.18 — Dashboard peak-exit analytics

## Cause

Front v10.7.17 implemented `PeakExitAnalysis` and rendered it in the Backtest workspace, but the Dashboard's `Backtest Analytics → Historical performance` screen uses `DashboardBacktestAnalyticsSection`, which did not render that component.

The Dashboard endpoint already returned `peak_exit_analysis` for completed Backtests through API v10.8.63, so no API change and no new backtest execution are required.

## Change

- Render `PeakExitAnalysis` directly in `DashboardBacktestAnalyticsSection`.
- Keep the existing guard inside `PeakExitAnalysis`, so processing types that do not expose `peak_exit_analysis` remain unaffected.
- Bump visible Front version to v10.7.18.

## Expected behavior

For a completed Backtest executed with API v10.8.63, Dashboard → Backtest Analytics displays, after the existing return/consistency analytics:

- median distance from peak;
- median peak capture;
- median max run-up;
- median sessions from peak to exit;
- median distance from peak by asset;
- exit distance and max run-up by operation;
- peak capture versus the next complete 10 sessions.

## Compatibility

API remains v10.8.63. Existing Backtests created before the peak-exit diagnostics schema can still be selected; the component shows the availability message rather than reconstructing historical diagnostics from mutable market data.
