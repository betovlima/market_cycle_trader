# Front v10.7.16 — independent Model Tuning Strategy

## Why

The TCC reference profile can be selected for Research/Simulation but cannot be used by the generic LightGBM tuning worker. The previous Model Tuning screen always displayed the Research selection, and therefore showed research-only Strategy #28 with no compatible baseline and a disabled Start Unified CARO button even when other compatible strategies existed.

## Change

The Baseline section now reads the dedicated `control.model_tuning_strategy_id`, displays a selection dropdown of compatible standard LightGBM and supported Temporal profiles, and invokes the existing administrator endpoint `POST /api/admin/strategies/{id}/select-for-model-tuning` using the optimistic control revision. The API v10.8.37 handler modifies only the tuning selection, not the Research/Backtest selection or protected Winner. The UI excludes reference-engine, MILP and unsupported stateful profiles, prevents changing a target during active tuning, refreshes the baseline and provides clear guidance for obtaining an exact matched new Backtest if none exists.

The Research Strategy remains selectable independently (including #28) for normal Simulation. No fallback of a TCC Control/Soft result to a standard tuning baseline is permitted. Existing capability gates and read-only restrictions remain. Added PT/ES translations and version/footer update.

## Compatibility and validation

- Must deploy with API v10.8.37; Front v10.7.16 displays its own version.
- Run `pnpm install --frozen-lockfile && pnpm build`.
- In Model Tuning choose a standard compatible Strategy. If no matching baseline exists, run a new Simulation of that Strategy and refresh. Selecting #28 for Research should not reset the independent tuning choice.
- No changes to Winner #27, current Paper holdings or model parameters are performed merely by deploying.
