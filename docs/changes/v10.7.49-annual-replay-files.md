# Front v10.7.49 | Arquivos históricos do Backtest na Reprodução Anual

Nova seção **Arquivos da execução** ao final da Reprodução Anual, visível para perfis que já possuem `annual_replay.view` ou `backtest.view`, inclusive o professor convidado.

A lista é obtida de `GET /api/analytics/backtests/{job_id}/files`, utilizando o mesmo `jobId` da animação. Downloads autenticados usam `downloadFile` (cookie da sessão) para o arquivo selecionado. A lista muda ao alternar o backtest; não usa os filtros de ano ou mês, pois os arquivos são da execução inteira.

Disponibilidades dependem dos registros reais, sem preencher lacunas. O manifesto SHA-256 e o pacote ZIP identificam a origem e as limitações: os arquivos resultam do analytics persistido e não substituem a base científica original do TCC.

Arquivos: `AnnualReplayFiles.jsx`, `AnnualReplayPage.jsx`, `annualReplay.css` e traduções PT/ES na `annualReplayTranslations.js` (EN é a chave original).

**Dependência obrigatória:** API v10.8.131, que libera explicitamente os endpoints para o `replay_guest`. A implantação precisa ser feita primeiro na API e depois no front. As operações Live/Paper, backtests, banco, estratégias, sinal e dados Alpaca não mudaram.

Validação: `pnpm test` (ou os testes definidos no `package.json`) e `pnpm build`; revisão/CI antes do merge.

## Correção de visibilidade da aba (29/10/2026)
A navegação exigia `annual_replay.view` estritamente, enquanto a página aceitava `backtest.view`. Algumas sessões com permissões legadas mostram Backtest, mas ocultavam Reprodução Anual. Agora o menu e a rota usam `canViewAnnualReplay`, que aceita qualquer das duas permissões, sem permitir acesso a usuários sem nenhuma delas. O professor continua restrito à Reprodução Anual. Teste em `tests/annual-replay.test.mjs`.

## Compatibilidade com a API de backtests históricos

A Reprodução Anual já carrega `GET /api/analytics/backtests/{job_id}`. A listagem e o download agora utilizam estes dados persistidos como fallback no navegador, inclusive quando `GET /api/analytics/backtests/{job_id}/files` não existir na API conectada. O frontend preserva a resposta bruta (sem normalização para o gráfico) e oferece apenas arquivos cujos dados foram recebidos: evolução do patrimônio, rotações, notas de decisão, métricas, analytics, manifesto SHA-256 e pacote ZIP (método STORE, sem nova dependência).

Não é necessário executar novamente um backtest antigo para fazer o download, desde que seus registros ainda estejam disponíveis no MongoDB para a API de analytics. Não há criação ou reconstrução de dados originais ausentes, nem alteração de ordens, estratégia ou estado operacional. O fluxo de API v10.8.131 permanece preferencial e o fallback é usado quando os endpoints de arquivos não existem ou retornam indisponibilidade. Teste: `tests/annual-replay-export.test.mjs`, executado pela CI do frontend.
