## Mudanças na interface

O painel **Conexão OAuth com a Alpaca** passa a ser apresentado na aba **Live** para o administrador do MCT. O usuário pode iniciar autorização, verificar a conexão e remover o vínculo local sem ter acesso ao token ou ao Client Secret.

1. **Conectar com a Alpaca:** chama `POST /api/alpaca-oauth/start` autenticado e redireciona o navegador para a URL de autorização emitida pela API.
2. **Retorno da Alpaca:** ao voltar ao MCT com o resultado resumido `alpaca_oauth` na URL, a aplicação abre a aba Live, apresenta o status do callback e remove o parâmetro da barra de endereço, preservando os demais parâmetros.
3. **Estado da conexão:** consulta `GET /api/alpaca-oauth/status`, exibindo ambiente Live, modo somente leitura e apenas os últimos caracteres do ID da conta.
4. **Verificar conexão:** consulta `GET /api/alpaca-oauth/verify` e atualiza os dados do Portfolio Live depois da verificação.
5. **Desconectar OAuth:** solicita confirmação, chama `POST /api/alpaca-oauth/disconnect` e atualiza a carteira pela origem tradicional, enquanto ela continuar autorizada para o administrador.

## Portfolio Live

A interface existente continua a utilizar `GET /api/live-market/portfolio`; a API decide qual cliente da Alpaca empregar com base na sessão administrativa e no token OAuth armazenado com segurança no backend.

- O cabeçalho identifica explicitamente **Acesso à corretora: OAuth da Alpaca (somente leitura)** quando `broker_authentication="oauth"`.
- Sem vínculo OAuth, apresenta **Chaves da Alpaca (somente leitura)** para a leitura legada.
- São mantidos os elementos atuais: valor da carteira, caixa, P/L não realizado, posição atual, gráfico de evolução, ordens, auditoria, relógio do mercado e telas de monitoramento Winner.
- Se uma consulta Live falhar, o componente remove os dados financeiros anteriores do estado e exibe a falha, evitando apresentar valores antigos como se fossem uma nova consulta válida.
- A exportação `portfolio/export.zip` utiliza o mesmo contexto OAuth da consulta, implementado na API.
- A conexão continua separada da autorização de **enviar ordens** e não habilita a Winner.

## Compatibilidade, restrições e segurança

- **Requer API v10.8.133** para `broker_authentication`, leitura OAuth e exportação consistente. É recomendável implantar a API primeiro.
- O frontend **não possui** `ALPACA_OAUTH_CLIENT_SECRET`, `ALPACA_OAUTH_ENCRYPTION_KEY` nem `ALPACA_OAUTH_CLIENT_ID`; as credenciais ficam no backend. Continua usando sua configuração normal `VITE_API_BASE_URL`.
- O vínculo é piloto apenas para o administrador e a conta Live esperada. Esta versão não libera Live para todos os usuários, não escolhe contas pelo navegador e não cria operações multiusuário.
- O frontend **não envia nem cancela ordens** via OAuth. Os controles operacionais da Winner continuam inalterados.
- Sem alteração de Trading (Paper), Research, TCC, sinal de compra/venda ou algoritmos de previsão.
